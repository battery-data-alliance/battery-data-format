Reference Datasets
==================

This page is the definitive catalog of the **canonical BDF example artifacts**: real battery
cycling measurements, each normalized from a raw vendor export and committed under
``docs/examples/reference/``. Every artifact on this page:

- was generated from a **raw vendor export published on Zenodo** under CC-BY-4.0
  (`10.5281/zenodo.18986774 <https://doi.org/10.5281/zenodo.18986774>`__), linked and
  checksummed below, so you can reproduce the conversion end to end;
- **reads back with full validation enabled** (``bdf.read(path, validate=True)``) — a test
  in CI enforces this for every file, on every commit;
- uses the **machine-readable notation** of the versioned
  `BDF ontology <https://battery-data-alliance.github.io/battery-data-format-ontology/pages/specification.html>`__
  as its on-disk column keys (e.g. ``test_time_second``, ``voltage_volt``,
  ``current_ampere``).

Column keys: what software should pin to
----------------------------------------

The on-disk headers are the normative form: one key per quantity, canonical unit baked in,
defined and versioned by the ontology. In memory, ``bdf.read`` exposes the same columns
under their human preferred labels (``Test Time / s``, ``Voltage / V``, …). Both forms
round-trip losslessly through ``bdf.save`` / ``bdf.read``, and deprecated aliases from
earlier ontology versions are normalized on read. Downstream tools should key on the
notation plus an ontology release version (pin one programmatically with
``ColumnOntology.load_version``).

Deliberately imperfect files
----------------------------

Artifacts whose filename carries a ``__Time_Bug`` or ``__Outlier_Bug`` suffix preserve real
acquisition problems **on purpose**, to demonstrate and test ``bdf.clean``. They are
format-compliant — they parse and validate — but the measured data contains the flagged
defect. Every file *without* such a suffix is clean. The machine-readable index
(``docs/examples/reference/datasets.json``) carries the same flag in its
``deliberate_data_bugs`` field.
