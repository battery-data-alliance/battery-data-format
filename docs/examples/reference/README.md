# Canonical BDF reference datasets

This directory contains the canonical, compliant example artifacts of the Battery Data Format: real cycler measurements, each normalized from a raw vendor export with `bdf.read` and saved with `bdf.save` defaults. Every file here reads back with full validation enabled (`bdf.read(path, validate=True)`), and a test enforces that on every CI run.

Each BDF artifact is paired with the raw vendor export it was generated from. The raw files are not committed to this repository; they are published on Zenodo under CC-BY-4.0 at [10.5281/zenodo.18986774](https://doi.org/10.5281/zenodo.18986774). The pairing — raw URL, checksum, plugin used, row/column inventory, and provenance — is recorded in [`datasets.json`](datasets.json), which is the machine-readable index of this directory. A human-readable version is rendered in the documentation under *Reference Datasets*.

## Column keys: the normative form

The column headers in these files are the **machine-readable notation** of the [BDF ontology](https://battery-data-alliance.github.io/battery-data-format-ontology/pages/specification.html) — e.g. `test_time_second`, `voltage_volt`, `current_ampere`. This is the normative, versioned form for software to key on: one key per quantity, with the canonical unit baked into the key. `bdf.read` exposes the same columns in memory under their human preferred labels (`Test Time / s`, `Voltage / V`, …); both forms round-trip losslessly, and deprecated aliases from earlier ontology versions are normalized on read.

## Deliberately imperfect files

Two artifacts keep real acquisition problems **on purpose**, to demonstrate and test `bdf.clean`:

- `SINTEF__SLPBA842124HV__2024-10-23__Rate_25degC__Neware__Time_Bug.bdf.csv` — non-monotonic test-time jumps as logged by the cycler.
- `SINTEF__NaCR32140-MP10-04__2025-08-25__CCCV_0p02C_25degC__BioLogic__Outlier_Bug.bdf.csv` — physically implausible voltage outlier spikes as logged by the instrument.

Both are *format*-compliant (they parse and validate); the bugs are in the measured data, and the `__Time_Bug` / `__Outlier_Bug` filename suffix is the marker. Every file without such a suffix is clean. `datasets.json` carries the same information in the `deliberate_data_bugs` field.

## File formats

Most artifacts are `.bdf.csv`. One (`...Novonix.bdf.parquet`) is a BDF parquet artifact: its raw export is 120 MB and parquet keeps the full 817k rows in 15 MB. Both formats are read identically by `bdf.read`.

## Regenerating

These files are generated by [`scripts/generate_zenodo_reference_bdf.py`](../../../scripts/generate_zenodo_reference_bdf.py); the exact invocation is recorded in `datasets.json` under `regenerated_with`. The script writes `.bdf.csv` outputs, so the Novonix parquet artifact is re-saved separately (`bdf.read` the raw file, `bdf.save` to `.bdf.parquet`). A few raw files on the Zenodo record have no committed BDF equivalent (too large, or no parser yet); they are listed with reasons under `unconverted_raw_files` in `datasets.json`.

## Adding a new pair

1. Upload the raw vendor export to the Zenodo record (new version) with the `PROVIDER__CELL__DATE__TEST__TEMP__VENDOR.ext` naming pattern.
2. Run the generator (or `bdf.read` + `bdf.save` manually) to produce the `.bdf.csv`.
3. Add the pair to `datasets.json` (provider, plugin, raw URL + checksum from the Zenodo API, and `deliberate_data_bugs` if applicable).
4. `tests/integration/test_reference_datasets.py` will fail until the manifest, the files on disk, and validation all agree.
